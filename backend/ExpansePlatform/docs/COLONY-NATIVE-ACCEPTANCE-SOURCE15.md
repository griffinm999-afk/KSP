# Source15 native acceptance addendum

Prepared 2026-10-03. This extends [the native acceptance sequence](COLONY-NATIVE-ACCEPTANCE-SEQUENCE.md), steps5,8,9, only for the new adapter gates. Native control remains stopped until root freezes the coherent candidate and obtains resumption. This document records no passed run and performs no implementation, build, harness or native action.

Use exact provider/integration/config bytes from [the source handoff](../../outputs/colony-brp15-implementation/README.md). Changed BRP or mismatched optional bytes, even with the same serializer name, must fail preflight **before startup**; unknown implementations are not runtime-fenced. Missing-dependency startup fixtures must not load the paid colony with physical part providers missing. The separate [bank candidate](COLONY-RANGER-POWER-BANK-CANDIDATE15.md) grants no unloaded remote grid or bank refuel endpoint.

Observe inactive settings/current stocks, then only the existing durable child may activate. Its historical SystemHeat-named provider grants no thermal certificate. Farm additionally requires `Plans[].Production[].Steps[]` `Kind="converterStart"`, `State="applied"`, exact `PartId/ModuleId/OptionHash`, before/after witnesses and matching `Effects[].Kind="productionNative"`.

2. **Warm observation, then later-UT recapture.** After activation, native PrepareRecipe/ProcessRecipe must expose the exact final recipe and multiplier together: existing internal `UtilityRecipeSample.Inputs/Outputs/Requirements`, `Ut`, `NativeMultiplier`, `MultiplierUt`, `MultiplierObserved`; multiplier/sample UT equal, age≤10s. Ranger multiplier1; farm uses its actual efficiency/Scientist. Early capture can produce `record=null` and hold. Once sample and applied receipt exist, ordinary loaded save or unload at **strictly later UT** invokes installed `OnGameStateSave→SaveVessel` / `OnUnloadVessel→SaveVessel`, rebuilding converters and retrying GetBehaviour. Same-UT save is a no-op; MarkDirty cannot repair null record. Prove one exact recaptured owner. No restart, repeated activation or generic substitute; first-paid commissioning recovery is separate from cold valid-record restoration.

3. **Warm/cold same-UT and startup authority gap.** Repeat a warm same-UT save/readback: resource quantities, activation flags, applied child ID and debit counts must stay unchanged. From the recaptured save, cold-load at its same UT and archive first before-time readback. Selected cached recipe/rate fields are cleared on a copied load tree and actual BRP rates recomputed before positive dt; unrelated native contributions remain. Physical inventory amounts/capacities and saved `IsActivated`/`isEnabled`/`EfficiencyBonus` must survive. Current mapping regenerates from actual identities, never durable cached indices. A valid record with temporarily unavailable ColonyRuntime authority produces an empty interval and future retry1,2,4,8,16,32,60s, persisted `authorityRetries`0…7. Readback must show finite retry UT strictly greater than current UT, then recovery without vessel visit or inventory mutation. Held-gap fuel/output remains zero and is not replayed. Permanent owner mismatch is held at infinity. A null initial record needs step2 rescan; it is not this retry case.

4. **Loader absence boundaries.** Separate startup fixtures test missing BRP, USITools, HarmonyKSP (`HarmonyInstallChecker.dll`) and KSPBurst: actual exclusion before GetTypes, no optional in loaded/MM lists, no Kopernicus/type-discovery poisoning. With pinned BRP but optional absent, cold-load a disposable recaptured save: selected vectors and fuel/Machinery rates zero before positive dt; quantities/activation and unrelated contributions preserved; qualification visibly held. Background absence does not forcibly disable foreground native hardware. Restoring absent optional requires loaded recapture; automatic recovery of an unknown missing behavior is not assumed.

5. **Three Kerbin days of inventory conservation.** Extend sequence step8 with at least64,800s actual UT while truly unloaded, preserving scene evidence and using the existing root-owned `warpTo`/`stopWarp` path. Start only after pending placement/crew effects finish. Archive each local Pu/Machinery tank and every input/output tank, actual module IDs, active flags, current vectors, rate/constraint/deadline, current people/efficiency, qualified support demand and all physical/owned receipts. A short loaded stock-ResourceBroker interval establishes actual stock input/output coefficients and current multiplier; compare the unloaded proportional interval with those stock semantics and its independently calculated decay bound. Do not label that short loaded interval as three days of observed foreground production. For isolated positive requirement A, use k=actual consumed ratio×actual multiplier/requirement ratio, actual BRP rate q∈[0,1], Aref=A0×exp(−k∫qdt), with per-epoch consumed fraction≤1e−4 and normalized cumulative error≤`1−exp(−kT×1e−4/(2(1−1e−4)))`. Segment at actual changes/refills/holds; missing rate history prevents a claimed full parity result. Do not compare against constant50 EC/s or constant nominal farm output. Full dumped EC can leave storage unchanged while Pu still declines; nondumped Supplies saturation must stop capacity-constrained production. Include unrelated solver events and a real constraint/rate change so the vector-epoch deadline cannot be postponed indefinitely. Actual physical stock = before + witnessed paid/native credits − witnessed debits/consumption; owned stock changes only by conserved receipts. Keep support, feeds, reorders and automatic intake explicit in that balance.
