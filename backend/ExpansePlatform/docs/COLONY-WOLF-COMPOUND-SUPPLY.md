# Combined paid WOLF supply

`ColonyEngine.QuoteWolfSupplies(state, colonyId, demands, environment)` reviews one current selected-save biome/depot and one bounded purchased package. It supports one to sixteen unique named requirements of 1–1000 unallocated WOLF points each. Points remain WOLF capacity; this path never credits physical cargo or colony-owned stock.

For two or more resources, the quote stores canonical sorted `Demands`. Raw extraction uses actual unlocked installed recipes with only their own geological vein and Power inputs. No crew points, veins, recipes, or production are synthesized. Candidates preserve any explicitly requested remaining vein capacity. Each commodity chooses one installed recipe type; the bounded comparison does not claim a global optimum over arbitrary mixtures. The Pareto comparison retains price, shared Power requirement, module count, and sequential manufacturing time, then chooses the lowest complete investment price, followed by manufacturing time, count, and deterministic recipe identity. Power output rounding and technology locks are included in the complete cost. An explicit desired unallocated Power balance is additional to the raw inputs.

The package includes at most 64 purchased modules, including new depot construction. Candidate search is bounded to 4096 frontier rows and 65,536 combinations per commodity; exceeding a bound gives an explicit blocker. Installed purchase costs and the existing modeled 10,800 UT seconds per module supplier lead time remain unchanged. There is one global WOLF supplier slot, and normal charter spending/founding limits, pending funds, and cash floor checks apply.

The command is `approveWolfSupplies` with exact reviewed `QuoteId` and only `Demand:<Resource>=<positive integer>` fields. `ReserveWolfQuote` is the shared internal reservation boundary. A parent production plan first quotes against the intact prior state, then replaces its exact future funding claim with the deterministic WOLF child in one detached transaction. The provisional claim release is not independently serialized or accepted; failure discards the entire transaction.

A one-resource vector delegates the preexisting scalar quote implementation. An empty additive `Demands` list writes no new hash bytes, preserving previously saved scalar quote identities. Nonempty vector hashes bind every demand plus all original purchase/depot terms. Paid-package replan checks every requirement while retaining exactly the purchased modules and price; it can only replace an unattempted preflight hold. The depot before witness can change during supplier manufacture, so a stale whole-depot witness prevents the first external mutation and retains the paid package for explicit replan.

The native adapter continues to pass all raw and shared Power module recipes in a single installed `Depot.Negotiate(List<IRecipe>)` call. Read-only IL inspection of the installed USI_WOLF1.0.0.0 confirms that this overload aggregates common input/output resources and records the offsets. Its underlying negotiation consumes before providing; exceptional atomicity is not guaranteed, and offset failures may only log. Therefore the adapter accepts the durable applying intent before any WOLF call, checks selected context after each setup callback, and accepts completion only after exact full-depot readback. Partial mutation, interruption, or lost acknowledgement stays held and cannot resend or replan. Even an observed expected after ledger alone is not treated as a native ownership receipt after an uncertain outcome. Terminal order state and full before/after witnesses prevent rearming after receipt compaction.

Provider lookup now resolves the current selected game's unique initialized `Game.scenarios` WOLF module reference instead of scanning all Unity objects. Registry readiness and unique actual depot identities are revalidated on every call; no registry from another save is cached. Both `Game.scenarios` and `ProtoScenarioModule.moduleName/moduleRef` were verified as public installed KSP members.

Validation at this source boundary: 30 focused combined/scalar WOLF and typed-copy tests passed; the WorldBridge Release build succeeded with zero warnings/errors; five read-only installed WOLF/scenario API contracts passed. Tests cover shared Power, complete investment cost, rounding/tech, exact module/vein limits, requested vein reserves, canonical hashes, payment/lead-time/allocation conservation, stale review, cross-colony cash/supplier ownership, all-demand paid replan, partial/lost acknowledgement holds, and legacy scalar binary hash compatibility. Native selected-game performance and paid combined allocation/save-reload proof remain assigned to the isolated acceptance owner; no game process, save, installation, or frozen native artifact was changed by this implementation.
