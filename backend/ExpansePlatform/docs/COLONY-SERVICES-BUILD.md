## Physical ownership and service

The installed `USI_ModuleFieldRepair` tank owns its Machinery, ReplacementParts or EnrichedUranium. A colony-owned staging reserve is a separate ledger. Service reserves accessible paid stock, preserving other reservations and the support floor. MaterialKits→ReplacementParts uses the installed USI maintenance one-to-one resource-unit mapping. No remote contractor can create an actual Engineer or native module bonus.

An actual ordinary Crew Engineer must occupy an installed `ModuleAutoRepairer` part within its installed RepairRange. The witness joins the current actual roster, exact workshop part and vessel identity; stale or duplicate crew mappings do not qualify. Actual selected registered inventory endpoint, part membership and provider capability are rechecked before the attempt. Both loaded/packed and supported unloaded BRP inventory paths use the existing `PhysicalInventoryTransfers` provider, with its exact `targetMemberId` filter. There is no second physical resource producer in this subsystem.

Before any physical callback the runtime prebuilds and accepts a held colony source debit, including source amount and exact physical target before-witness. The inventory gateway supplies apply, synchronize and exact readback. Only success swaps in the prebuilt completion. A confirmed exact rollback may release the original source reservation; uncertain effects retain held stock and cannot be cancelled by granting an unknown refund. The KSP save boundary persists these witnesses; unsaved changes do not acquire crash-durability by terminology.

Recurring service defaults disabled. A saved enabled policy has at least 21,600 UT seconds cadence, bounded target fill and at most four new current-tick operations. It requires the same real stock and physical worker/provider as manual service. Historical ticks do not invent old tank measurements. The desktop form reviews exact stock debit and target capacity; the in-game row details show the proposed accessible reserve debit before Service now.

## Utility evidence

The implemented continuous-source path is the installed stock RTG with no consumable input, an actual same-vessel ElectricCharge ALL_VESSEL path and enabled owned tanks. The provider checks current active generation and conservatively accounts command/wheel demands, light resource use, the actual configured kOS instruction/disk bound and active processing. Active industrial recipes and unreviewed module demands produce explicit holds. Nominal demand bounds are labeled as bounds; observed storage delta is a separate short-window net measurement and cannot certify power reliability or complete throughput.

Passive stock RTG heat qualification checks its installed passive equilibrium/core limits plus actual part/core temperature margins. Active reactor/drill cores require separately qualified radiator evidence. External PDU range/module presence never becomes a verified distribution edge. Qualified support is reevaluated from a current report before an actual resident arrival rather than relying indefinitely on a stale facility flag.

Unloaded continuation requires the supported actual BRP processor, fresh provider-owned RTG recipe/output witness and a prior commissioned unchanged passive thermal proof. Proto temperatures remain saved observations; they are not fresh live measurements. The installed BRP implementation does not process loaded vessels, including packed loaded vessels; the packed path therefore uses the native loaded hardware, not invented BRP production. Actual loaded/packed/unloaded game tests remain necessary to certify these paths.

Certified homes require the construction provider's sealed explicit persistent-part mapping and exact current loaded/proto placement markers. Only declared deployed KPBS Habitat MK2 craft home IDs are eligible. Unloaded deployed capacity comes from persisted PlanetaryModule animation state, not the prefab's nominal seat count. Hubs, airlocks, industrial seats and arbitrary callbacks cannot become homes through CrewCapacity alone.
