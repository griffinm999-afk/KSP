# Registered physical inventory and owned colony stock

Implemented in `ColonyPlanningPhysicalRecords/Engine/Codec.cs` and `ColonyRuntime.PhysicalProcurement.cs`. This is one resource owner transition through the existing exact physical inventory gateways. Native MKS/WOLF/BRP retain production; no extra modeled output or WOLF capacity becomes commodity stock.

## Review and authorization

`env.Planning.LocalStocks` contains bounded actual registered adopted tank observations. The normal path requires the selected-save endpoint, unique persistent tank identity, actual local warehouse transfer enabled, actual unlocked resource flow, same landed body, colony boundary and the installed `LOGISTICS_SETTINGS.ScavangeRange`. Loaded tanks use actual PartResource, including anchored packed vessels. Unloaded tanks require coherent actual BRP inventories and synchronized proto/config witnesses after native catch-up. Unsupported or uncertain provider/readback holds; no unanchor operation exists.

`QuotePhysicalTransfer(state,colonyId,localStockId,direction,amountMicro,env)` describes physical and owned before/after amounts. `transferColonyStock` submits the current exact quote ID, `TargetId=LocalStockId`, `Direction=toColony|toPhysical`, and `AmountMicroUnits`. `cancelPhysicalTransfer` releases only an unattempted reserved operation; an uncertain physical attempt cannot be cancelled into a guessed refund. UI uses named tanks and ordinary units. Environment bounds are 1024 local tank rows, access/membership witnesses128, context256, title160, worker/reason512.

Approved founding/reorder and automatic service policies first obtain an actual local shortfall. This path defaults enabled unless `configurePhysicalProcurement Enabled=false` explicitly disables it. Outbound native converter buffers require `Enabled=true`; the balance model uses 5-UT-second reviews, at most1000 units per transfer, and at most50% actual input tank capacity. Inbound withdrawal preserves that same native input reserve, preventing an automatic fill/drain cycle. Manual outbound transfers may use additional capacity only within actual tank limits and actual unreserved owned stock above the support floor.

## Installed recipe and Machinery ownership

Loaded native input names come from the passive final native `PrepareRecipe` return observer. The adapter does not invoke `PrepareRecipe`, does not substitute `BaseConverter.inputList` for actual USI swapped bays, and holds when a current same-context active recipe sample is missing. Unloaded names come from actual current BRP converter inputs after authoritative catch-up. Native converter observation is bounded and cached once per vessel for one environment snapshot; depot observation is cached once per registered endpoint for that snapshot. Actual frame costs still need runtime profiling.

Machinery has a separate `maintenanceReserve` classification. Installed `USI_ModuleFieldRepair.Replenish` uses regional warehouse stock only from source parts without a BaseConverter and with local transfer enabled. The adapter follows that rule and additionally requires an actual Engineer in a separate supported AutoRepairer within its installed repair range. Loaded actual hardware and unloaded matching installed module identities must establish the reserve distinction. Installed converter Machinery never appears as generic warehouse stock. Services exclude pure Machinery warehouses from automatic refill targets, so warehouse withdrawal cannot trigger a refill of the same reserve. An approved service policy may obtain its missing owned Machinery from an accessible reserve before the existing qualified installed-tank service worker applies it. ReplacementParts/nuclear service paths retain their separate installed target qualification.

## Saved conservation and uncertainty

Inbound reservations own receiving capacity (`Stock.IncomingReserved`). Outbound reservations own unreserved source quantity (`Stock.Reserved`), protecting support, construction and other service/material claims. An exact tank has one pending operation across all colonies and service destinations. The legacy selector skips these exact claims and exposes a transient hold; it does not advance a rule or remove due cargo. Other unreserved work may continue. The final EffectBridge guard remains after retained receipt reconciliation and before native provider preflight. A final racing no-effect rejection changes no accepted logistics state; Host manual request terminal status is distinct from game-owned scheduled cargo retry.

Before physical mutation, the runtime prebuilds serialized held, complete and confirmed-rollback states. The synchronous hold reference swap happens before any provider callback can save. Outbound owned stock moves into held escrow before physical credit; inbound owned stock is credited only after exact physical debit, synchronization and readback. The selected game/load/registry and boundary are checked again after synchronization. Confirmed rollback restores the prior reservation state and releases it. Any partial apply, uncertain rollback, save-context change or thrown callback retains the durable hold. Reload never repeats a held debit/credit or assumes an intended witness means success. The colony/legacy authority guards stop new external writes around this uncertainty.

Physical lots retain imported attribution. Exact outbound imported stock follows delivery; exact return cannot become local production. Observed native movement sets an uncertainty marker, and once imported stock has occupied that tank the marker conservatively attributes returned mixed stock as imported. Depletion does not erase the persistent `HadImportedStock` marker. Actual physical output without a colony import history remains actual physical stock; its operation records that limited provenance statement rather than claiming synthetic production. Opening physical stock has no invented quantity or funds.

## Approved import maximum and local substitution

The original reviewed import amount, price, freight and travel remain immutable. Progress records `SubstitutedLocallyAmount` separately. Only a completed exact inbound operation belonging to the same plan/resource can increase it. Effective future purchase amount equals original minus substitution; effective price is the original per-unit ceiling plus original freight when quantity remains. Quantity and cost can only decrease. Remaining cash and future supplier claims release exactly that difference; already dispatched cargo preserves original terms. Materials transfer atomically into the plan's reserved material owner. Save validation checks immutable bills, receipt proof, supplier/funding arithmetic and material/capacity claims.

The immutable quote hash uses its original canonical import projection, excluding the additive progress field. Previously saved paid plan quote hashes continue to validate after the schema extension; original paid scope is never silently requoted.
