# Colony package, installation and binary rollback

The new tooling produces a reproducible **candidate**, with native acceptance and template certification still open. `package-colony.ps1` refuses release status and false template certification. There is no production override. Candidate installation defaults to refusal; `IsolatedTestCandidate` works only with an explicitly marked disposable `artifacts/colony-release-fixtures/<32 hex id>` tree in the source workspace, four exact sibling roots named Game, App, State and Backup, and a fake game executable containing that fixture ID. It refuses a real executable. The distributable copy of the installer cannot use this source-workspace mode.

The current candidate is local/private and has not been distributed externally. Redaction covers public documentation and manifest fields; local source/evidence origin reports stay outside the archive. Exact reviewed binaries can retain absolute local source/PDB paths in compiler CodeView debug metadata. The archive is therefore not claimed to be byte-level path-free. A future reproducible release should use reviewed `PathMap` build inputs and new verified hashes for every affected assembly, including Foundation. The current tool preserves the tested frozen DLL bytes and does not strip or rebuild their debug records.

After source validation, snapshotting may additionally pin ToolEvidencePath/ExpectedToolEvidenceSha256 and NativeReviewPath/ExpectedNativeReviewSha256. These records stay local; only sanitized IDs and digests enter the archive. A development freeze review and disconnected filesystem/UI checks are candidate provenance, not native product certification.

Use PowerShell 7 on Windows. Build the independent Host and Manager in Release before snapshotting. The Windows apps require the external .NET 8 Desktop Runtime. The package carries the exact matching net472 Bridge/Domain from the pinned immutable freeze, both net8 app runtimes, four colony configuration files, ten craft files and ten corresponding manifests, their catalog, all seven Foundation package files, documentation and installation/rollback tools. The expected Foundation DLL is SHA256 `1D5138568042C9F510A11C6F580EC6652BFDF883EAC7DE32E97688CF372799EB`. No harness, test request, save, token or private log is included.

The default `legacy14` payload profile retains the original exact63-file allowlist and verifies immutable14 archives. `new-colony-package-input.ps1 -PayloadProfile source15` prepares a separate69-file candidate: it additionally requires the Ranger bank craft/manifest, `Plugins/Expanse.BrpColony.dll`, `Optional/BrpColony.cfg`, the bank engineering guide and the prerequisite tool. The optional adapter targets net481; Bridge/Domain remain net472. All managed game inputs must occur in the newly pinned freeze, including the bank and optional integration. Snapshotting never combines later source15 game files with frozen14 authority. It also binds the optional assembly's portable PDB to current source checksums and its exact frozen bytes. No third-party BRP, USITools, Harmony or KSPBurst DLL is redistributed. An incomplete optional pair, unknown payload profile, extra DLL, unlisted source-cache hash or differing catalog/individual quote and engineering terms holds packaging. Native certification remains false for every template.

Source15 requires exact installed dependency bytes and managed/loader identities before any apply and again after apply. It refuses absent dependencies and mismatched BRP or optional integration; it has no installer mode that relaxes this boundary. The actual Harmony loader provider is `000_Harmony/HarmonyInstallChecker.dll` registering HarmonyKSP1.0.0; the separate `0Harmony.dll` runtime is also pinned. Actual KSPBurst registers1.7.4, satisfying the adapter's declared minimum1.5.5. USITools has managed version1.0.0.0 and loader filename/versionUSITools0.0.0. The adapter must carry all four reviewed KSP loader dependencies, including BRP's transitive HarmonyKSP/KSPBurst exclusions, and its config must modify only the existing USI handler under the exact conditional `NEEDS` guard.

Before every manual start of this candidate, run `test-colony-prerequisites.ps1 -GameRoot <explicit root> -ExpectedOptionalAssemblySha256 <reviewed package OptionalIntegrationBasis.AssemblySha256>`. This reads hashes and PE metadata without loading product or third-party assemblies, changing files, launching a game, or granting native qualification. It checks the installed optional config and rejects duplicated or renamed provider/integration assemblies discovered under GameData. Keep the archive and reviewed manifest digest to obtain the expected optional hash. Repeat the check after any mod/file changes; the tooling does not lock external writers or control later launches. Known exact BRP with an absent optional integration has a managed cold nonproducing path. An unknown BRP or a changed optional DLL retaining the serializer name is **not** proven runtime-fenced and must not be started. Arbitrary later mod upgrades or file replacement are outside this candidate's supported boundary.

Source15 rollback follows the same immutable receipt and unchanged-save/state guards. Newly added optional DLL/config files are removed only when their bytes match the receipt; recorded prior files are restored exactly. Interrupted recovery accepts only recorded old/new hashes. An unknown stale optional filename or an optional DLL with a different hash holds preflight instead of silently cleaning it up. Use the earlier matching receipt to remove an earlier integration before installing a different reviewed candidate; do not delete files or invent a replacement receipt to bypass drift guards. Source15 recovery also requires the reviewed provider environment, and holds if dependencies changed during the transaction.

`new-colony-package-input.ps1` requires ReleaseId, FreezeManifestPath/ExpectedFreezeManifestSha256, BuildEvidencePath/ExpectedBuildEvidenceSha256, UiEvidencePath/ExpectedUiEvidenceSha256 and a new OutputRoot. It snapshots rather than building or changing the frozen directory. It binds portable-PDB identities to their compiled assemblies, verifies non-generated compiler document checksums against current source, and requires the frozen net472 Domain and the net8 Domain to share exact source document/checksum sets. Changed-but-unbuilt app source holds snapshotting. Host/Manager/Core/Foundation compiled-source proofs and the Domain proof are pinned local provenance. Review its local input manifest, then call `package-colony.ps1 -InputManifestPath <input> -ExpectedInputManifestSha256 <reviewed hash> -OutputRoot <new output>`. Input hashes fence concurrent edits. Each archive entry is sorted and has a fixed timestamp; equivalent inputs produce identical archive bytes. The archive has a relative file allowlist and sanitized public documentation. Absolute source/evidence paths and their origin report remain in the local build report outside the archive. Source/build/evidence digests establish provenance, not native qualification. Current source hashes do not claim that the frozen Bridge was built from later source changes; its authority is the pinned freeze manifest.

All installer parameters are explicit: ArchivePath, ExpectedArchiveSha256, GameRoot, AppRoot, StateRoot, BackupRoot, SelectedSaveRelativePath and ExpectedSaveSha256. The selected path must be `saves/<name>/persistent.sfs`. Roots must already exist and must not overlap. BackupRoot must be outside the game, apps and app state; backup DLLs must never be under GameData. Versioned apps live under `AppRoot/versions/<ReleaseId>`; `current.json` identifies the reviewed version. The installer never launches anything. Select its Host/Manager executables manually, retaining the explicitly selected state location and matching configuration. Legacy funds/delivery documentation remains included; old source launcher examples are historical and are not installation instructions for this package.

Before changing any target, the installer checks the pinned archive, exact entries, file hashes, catalog identities/craft hashes, Foundation hash, app runtime versions and matching shared app assemblies. It rejects unexpected managed DLLs/files, traversal, duplicate or missing entries, alternate streams, reparse points, hard links and conflicting roots. It refuses target KSP/Host/Manager processes and relevant dotnet processes, including a Host from another binary directory using the selected `--data-dir` or default state path. Close them yourself; the tool never kills or starts processes. Process ownership that cannot be determined also holds installation. It rechecks process closure and the exact target hash/absence after preparing a temporary copy and immediately before replacement. A small operating-system race between that final check and rename remains; this is an offline installer, not a lock on every external writer. Do not start applications or edit managed files during install/recovery.

The backup contains the complete prior managed game files, all versioned app files and pointer, app state and selected save directory (including quicksaves), with hashes checked again before apply. Installation changes binaries/configuration, app version files and the pointer only. An immutable `receipt.json` is written before the first change, and its path/SHA256 are printed. Keep that digest. Per-file temporary copies are verified before atomic replacement. `status.json` is advisory and never authorizes recovery. A failed apply or completion-status write attempts to restore the recorded binary baseline. If recovery is held, the printed immutable receipt remains the recovery authority. Failed preflight staging and all backups are retained for inspection; the tooling never recursively deletes them.

`rollback-colony.ps1` requires ReceiptPath, ExpectedReceiptSha256 and the same four roots. Ordinary rollback requires the exact complete installed binary/config/app inventory, including all prior app versions; changed, missing or extra bytes hold it. `-RecoverIncomplete` instead permits only each recorded old/new file hash, declared before-absence for newly created files, and a crashed temporary copy whose bytes exactly match a prefix of its retained old or new source. It rejects unknown bytes and missing prior files. All retained sources and backups must still match their receipt hashes. The receipt must be inside the matching external backup transaction. Recovery can be retried if interrupted: a known restored baseline is accepted by RecoverIncomplete. Completion-status writes are optional evidence; no replacement operation is invented.

Rollback defaults to **binaries only** and keeps current saves and app state. Every rollback, including automatic failed-install recovery, requires their complete inventories to equal the original baseline before changing binaries. Advanced or migrated state holds rollback; it is never rewritten to satisfy that check. `-RestoreUnchangedSaveAndState` records explicit unchanged-baseline semantics; the identical files already present are retained without rewriting them. The tool never blindly rewinds play progress or installs an older binary against changed play/state. Retain advanced saves/state and use a qualified matching runtime before further play. The save and economic/schema authority remains in the selected save as described in the operator and delivery guides. The backup does not replace that authority.

`test-colony-release.ps1` takes the reviewed ArchivePath/ExpectedArchiveSha256 and InputManifestPath/ExpectedInputManifestSha256. It creates only new marked workspace fixture trees with fake executables and fake old binaries. Its process observations and fault injection replace private module functions in the test process, not a public installer bypass, and restore the shipping process function before returning. It exercises corruption, missing/extra entries and DLLs, stale hashes, path/link attacks, running targets, root mismatch, interrupted apply/status writes, drift holds, complete binary rollback and preservation of changed play progress. These are filesystem fixtures, not native acceptance or a live install.

`test-colony-source15-tooling.ps1` provides bounded source/helper validation before a coherent source15 archive exists. It creates only new disposable workspace trees, verifies the original14 allowlist and source15/catalog checks, reads an existing compiled adapter's metadata without executing it, and mocks provider PE observations only inside the fixture module. Its fake-file transaction checks demonstrate exact optional removal/restoration; they do not install an application or qualify a real dependency environment. Final15 archive creation, reproducibility and full archive transaction tests still require the approved coherent freeze. Preserve earlier failed fixture logs alongside the final result.
