Verified against integrated primary `src/Expanse.Clock.Core/ColonyLifeSupportTelemetryProtocol.cs` and Bridge `PowerAverageTelemetryMath.cs`.

1. `powerAverage.windowId` is a JSON integer backed by Int64, inclusive range 1..9007199254740991. Its `status` is exactly `observed` or `partial`.
2. USI `captureSequence` is an Int64 positive integer in the same safe-integer range. `crewCount` is an Int32 integer in 1..4096 inclusive and must equal the containing vessel row's crew count. All lifeSupport/powerAverage `reason` values must be non-null strings of at most 360 .NET UTF-16 code units; empty strings are allowed.
3. Stream validation permits `processedEndUt <= sampleUt + 1e-6` absolute game seconds and requires `processedEndUt >= intervalGameSeconds`. `sampleUt <= lifeSupport.observedUt`, with age at most 10 game seconds. A trailing processed endpoint represents historical catch-up. Backend has no separate current-rate classification rule; a frontend equality test can use absolute 1e-6 seconds, rather than the generic relative `Near` helper used for arithmetic identities. The latter allows max(1e-9, abs(expected)*1e-6).
4. Partial rows from one shared window may have different `coveredGameSeconds`. Interval sets are not transmitted, so their common intersection cannot be recovered. Sum accepted amounts only for matching outer session/load epoch, windowId and bounds and label the result a measured subtotal with missing coverage. Retain each row's covered duration. Do not sum denominators or present summed per-vessel covered means as a complete colony mean. A subtotal divided by full `windowGameSeconds` can only be labeled measured amount per reporting span with gaps unknown. A complete colony mean requires all required vessels with compatible full coverage.

The immutable staged archive remains unchanged. This document clarifies its existing contract; it is not a code change or a new package.

Paused versus unloaded display: a fresh paused frame can retain an emitted completed window as a historical readout, with its original window identity/bounds and increasing monotonic `ageRealSeconds`. Pause interrupts pending power coverage but does not itself invalidate completed averages. Do not present this as current generation/consumption or reset its age because a fresh frame arrived. It disappears when the backend clears the completed cache on a subsequent report, expires after 120 real seconds, or invalidates the context/mode. Unloaded/snapshot rows are excluded by the Bridge: it invalidates that vessel's average and does not emit one. Core's average validator itself has no loaded-basis condition, so the frontend should also exclude an inconsistent snapshot/unloaded average from the operational display; any separately retained prior window is explicitly historical and preserves original age. A loaded packed vessel is distinct from an unloaded snapshot and can emit a partial native window.
